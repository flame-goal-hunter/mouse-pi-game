# Публикация игры на Heroku

Один Heroku-приложение раздаёт **и саму игру** (как устанавливаемое PWA), **и сервер снежков**
(Colyseus по WebSocket). Один адрес, один дино, никакого CORS.

## Что уже готово в репозитории

- `Procfile` → `web: node server/src/index.js`
- корневой `package.json` → `start`, зависимости сервера, `engines.node = 20.x`
- `server/src/index.js` раздаёт папку `www` и слушает `process.env.PORT`
- клиент сам подключается к мультиплееру по адресу текущего сайта (порт не нужен)
- PWA: `www/manifest.webmanifest`, `www/sw.js`, иконки в `www/assets/icons`

## Вариант A — деплой из GitHub (Heroku подключён к приватному репозиторию)

1. Запушить репозиторий на GitHub (приватный — исходники никуда не публикуются).
2. Heroku → приложение → **Deploy** → *Deployment method* = **GitHub** → авторизовать и выбрать репозиторий.
3. В *Automatic deploys* оставить ветку **`main`** (она уже основная в репозитории и
   содержит актуальную игру) и включить автодеплой, либо жать *Deploy Branch* вручную.
4. Один раз: **Resources → Change dyno type → Basic** (иначе дино засыпает и первый заход ждёт пробуждения).

Больше ничего настраивать не нужно: Heroku сам увидит `Procfile`, поставит зависимости
по `package-lock.json` и запустит `node server/src/index.js`.

При каждом деплое `heroku-postbuild` штампует версию кеша service worker номером коммита,
поэтому у всех, кто уже установил игру, она обновится сама — вручную ничего править не надо.

Репозиторий: `https://github.com/flame-goal-hunter/mouse-pi-game` (приватный).
Основная ветка — `main`. Ветки `master`, `network_mode` и остальные оставлены как история;
деплоить из них не нужно.

## Вариант B — деплой напрямую из терминала

```bash
# 1. Войти (откроется браузер)
heroku login

# 2. Создать приложение (имя станет частью адреса) и привязать его к репозиторию
heroku create mousie-pi          # → https://mousie-pi-<hash>.herokuapp.com

# 3. Никогда не засыпать: Basic-дино (иначе первый заход ждёт пробуждения ~10-30 c)
heroku ps:type web=basic

# 4. Выложить текущую ветку
git push heroku main:main

# 5. Открыть
heroku open
```

## Обновление после правок

- **Вариант A:** просто `git push` из ветки `main` — Heroku подхватит сам (если включён автодеплой).
- **Вариант B:** `git push heroku main:main`.

Версию кеша service worker вручную поднимать **не нужно** — `tools/stamp_sw.mjs` подставляет
номер коммита на каждой сборке.

## Проверка

```bash
curl -s https://<адрес>/health                       # {"ok":true,...}
curl -s -X POST https://<адрес>/matchmake/joinOrCreate/snowball   # выдаст комнату
heroku logs --tail
```

## Заметки

- Исходники **не публикуются** — Heroku хранит их у себя, наружу видна только игра.
- Игру может открыть любой, кто знает адрес. Если нужно ограничить круг — добавьте код
  приглашения на первом экране или базовую HTTP-авторизацию в `server/src/index.js`.
- Дино раздаёт статику сам: первый заход ~15 МБ, дальше всё берётся из кеша service worker.
- Панель Colyseus для отладки: `https://<адрес>/colyseus`.
